## 0. 结论速览

1. **首要风险不是「zed 字样」，而是许可证**：主体是 GPL-3.0-or-later
   （逐 crate 统计 `crates/*/Cargo.toml` 的 `license` 字段：204 个 GPL-3.0-or-later、
   30 个 Apache-2.0）。闭源商用分发本就不满足 GPL-3.0，需法务先定路线。
   本文后续所有条目都是「商标/品牌」线的工作，**不能替代许可证线的结论**。

2. **两个方向相反的动作必须同时成立**：
   - **运行期可见面**（字符串、路径名、资产、网络、生成文件）要清干净；
   - **法律文本与版权头**（`LICENSE-GPL`、`LICENSE-APACHE`、源码版权声明）必须原地保留。
   为了去字样而删版权头 = 当场违反 GPL。可以加自己的声明，不能删别人的。

3. **二进制基线当前未归零**（2026-09-26 实测）：

   - 独立单词 `Zed`：284 行
   - `zed.dev`：91 行
   - `zed://`：16 行
   - `x-zed-*`：13 行
   - `ZED_*` 环境变量/常量：20 个（去重）
   - `Zed Industries`：4 行
   - 编译期源文件路径串（`crates/zed/src/`）：15 行

4. **全局应用名的单一来源仍是 `Zed`**：`crates/paths/src/paths.rs:18`
   `pub const APP_NAME: &str = "Zed";`。OHOS 数据根已特判为 `HiCodeer`
   （`crates/paths/src/paths.rs:103`、`:144`，详见 `2026-09-14-ohos-data-root-layout.md`），
   但 `APP_NAME` 本身没改，它仍驱动窗口标题、日志文件名 `<AppName>.log`、
   以及非 OHOS 平台上的 XDG 目录名。

5. **产品会在用户项目里生成 `.zed/` 目录**：路径**硬编码**在
   `crates/paths/src/paths.rs:503`（`RelPath::from_unix_str(".zed/settings.json")`），
   不从 `APP_NAME` 推导。这是「程序生成的文件」里最需要单独决策的一项
   （改名会影响用户已有仓库的兼容）。

6. **交付判据**：第 11 节的门禁命令输出归零，且第 1 节的法务结论已落。

## 1. 合规硬约束（先决条件，未决）

- **许可证分布**：204 个 crate 为 `GPL-3.0-or-later`，30 个为 `Apache-2.0`
  （逐 crate 读 `crates/*/Cargo.toml`）。主程序 `crates/zed/Cargo.toml:7`
   为 `GPL-3.0-or-later`。仓库未发现 AGPL 成分。
- **GPL-3.0 的两项硬义务**（与是否改名字无关）：
  - 分发二进制时，必须让接收者能取得完整对应的源码（含我们的修改）；
  - 必须保留原有的版权声明与许可证文本。
- **商标与版权是两条独立风险线**：清掉所有「Zed」字样**不等于**可以自由商用；
  同理，GPL 允许收费分发，但要求开源衍生作品。
- **因此本清点的定位**：他是「商标/品牌线」的作业清单。
  「GPL 线」需法务给出结论后再决定交付形态。

### 必须保留（禁止顺手删除）

- `LICENSE-GPL`、`LICENSE-APACHE`
- 各源文件头部版权声明，例如
  `crates/gpui_linux/src/linux/x11/clipboard.rs:2`
  （`Copyright 2022 - 2025 Zed Industries, Inc.`）
- 第三方依赖自身的许可与署名（`script/licenses/zed-licenses.toml` 是汇总工具，
  可保留但需重跑出我们自己的清单）

## 11. 交付前门禁（已固化为脚本）

脚本：`移植记录/zed问题定位手段/zedscan.py`（与 `psrch.py` 并列，2026-09-26 建）。

```sh
python3 移植记录/zed问题定位手段/zedscan.py                 # 计数 + 样本 + 判定
python3 移植记录/zed问题定位手段/zedscan.py --quiet         # 只出计数与判定，适合构建日志
python3 移植记录/zed问题定位手段/zedscan.py --samples 0     # 不打印样本
```

行为：

- 覆盖第 2 节的 7 个维度，逐项给出「当前 / 基线 2026-09-26 / 变化」，与脚本内置基线比对；
- 退出码：仍有命中返回 1，全部归零返回 0 —— 可直接当门禁用；
- 命中时打印样本，便于定位来源；
- 扫描耗时约 1.5 秒（308 MB 产物），内部用 `strings -n 7` 口径；
- 他覆盖的是**商标/品牌线**；许可证线见第 1 节，不由脚本判定。

两个坑：

- 本仓 `grep` 对部分路径会**静默失效**（见
  `移植记录/zed问题定位手段/psrch.py` 的文件头说明）。
  脚本自身按行读 `strings` 输出、不经 `grep`，不受影响；
  但若把范围扩到**仓库目录**做「零命中」结论，仍必须用 `psrch.py` 或 Read 复核。
- 脚本基线是 `strings -n 7` + 按行统计的产物；换口径（如 `-n 6`、`grep -a`）
  会让计数偏离基线，改口径前先确认。
