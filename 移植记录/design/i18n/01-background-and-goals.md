# 第 1 章 背景与目标

## 1.1 项目

- 项目名：HiCodeer。
- 来源：Zed 编辑器（`zed-industries/zed`）的 OpenHarmony（OHOS / HarmonyOS NEXT）移植仓库，仓库根 `/storage/Users/currentUser/workspace/hicodeer`。
- 当时版本：**1.23.0**（注意：真实上游基点约等于上游 2026-08-15 的提交 `9bde578`，`version = 1.17.0` 只是 tag，见第 4 章版本对照）。

## 1.2 起点决策与本次方向反转

- 此前曾做过一次决策：**移除 i18n、界面统一英文**——菜单回退英文硬编码、删掉 `zed_i18n`、去掉语言设置项。
- 本次是**方向反转**：重新引入多语种，落地中文界面。
- 反转的理由（本任务的直接驱动）：交付物需要中文界面，且要有一套**可扩展**的多语种框架（以后能加日语、韩语等），而不是只做一次性的硬编码汉化。

## 1.3 交付目标

1. **中文界面落地**：设置页、菜单、命令面板等可见 UI 文案显示中文。
2. **可扩展的多语种框架**：新语言只需补一份词表 + 重新生成语言包，不必再动代码结构。

## 1.4 硬约束

这些约束在后续每一步都要满足，是选型与实现的前提：

- **许可证**：仓库是 `GPL-3.0-or-later`。任何引入的方案、词表、工具，其许可证必须与交付物相容。
- **商用去 Zed 化**：交付物**不得含任何 Zed 字样 / 资产**（包括界面文案里的 `Zed`、品牌词、协议命名空间等）。因此汉化词表里凡是含 `Zed` 的译文必须清洗（规模见第 4 章，替换目标属**产品命名决策**，未定前不能擅自替换）。
- **不得改 OHOS 适配既有行为**：本次仅做多语种，不能顺带改动 OHOS 移植已有的行为逻辑；改动面要能被逐行追溯到「加多语种」这一件事。

## 1.5 本章小结

- 目标明确：**中文界面 + 可扩展框架**。
- 约束明确：GPL 许可、去 Zed、不动 OHOS 既有行为。
- 这三条决定了后面「选哪个方案、怎么把改动面控制住」的全部取舍。
