# 第 14 章 关键决策记录

用「决策 / 备选 / 理由」的形式记录本次的关键取舍，便于以后复盘与复用。

## 决策 1：选 `LI-NA/zed-i18n` 作为方案

- **决策**：采用 `LI-NA/zed-i18n`（工具链式 + 独立 crate + 宏查表 + 字节偏移回注）。
- **备选**：
  - `x6nux/zed-globalization`（整包分发预编译中文版，1005 星）。
  - `TC999/zed-loc`（427 星，按文件路径组织翻译表，每晚自动构建）。
- **理由**：
  - `x6nux` **整包无法回注**——它给的是改好的成品，不是能作用到我们源码树的工具；而且夹带与汉化无关的改动。
  - `TC999` 翻译表**按文件路径组织**，**版本一变即失效**；且**提取脚本仅 Windows 可跑**（我们在 Linux）。
  - `LI-NA` 是**工具链式**且以**字节偏移**定位回注，能对准**我们自己的源码树**；许可证（内容 GPL-3.0 / 工具 MIT / crate GPL-3.0-or-later）与本项目相容。

## 决策 2：必须对新树重跑 extract

- **决策**：对我们的 **1.23** 树重新跑 `extract`，而不是直接用它的 1.21 词表 / manifest。
- **备选**：直接用 `LI-NA` 自带的 1.21 manifest 回注。
- **理由**：manifest 里的 `start_byte` / `end_byte` 是**字节级偏移**，**只对 1.21 的源码树有效**。直接拿 1.21 的偏移回注 1.23 树会打错位置。重提取后偏移才对准 1.23。

## 决策 3：先做「骨架 + 语言包」，不直接全量回注

- **决策**：先落地运行时骨架（`localization` crate）+ 语言包，验证链路与可见效果；全量回注放到第二步。
- **备选**：一步到位做全量回注（7000+ 处、400+ 文件的大 diff）。
- **理由**：
  - 先**验证链路**（编译能过、语言包能生效、界面能看到中文），再放大改动量。
  - 控制单步 **diff 规模**，降低排查难度；全量回注涉及 400+ 文件，风险面大。

## 决策 4：用「运行时查表」而不是「按语言逐套字节补丁」

- **决策**：走 `apply-universal` 路线——回注一次（把字面量包成 `localized_str!`），运行时按 locale 查表。
- **备选**：按语言逐套做字节补丁（每种语言各回注一遍源码）。
- **理由**：
  - 运行时查表**回注一次即可**支持多语言；加语言只需补词表 + 重新生成语言包。
  - 逐套字节补丁意味着**每种语言都要改一遍源码**，且彼此冲突，无法共存。

## 决策 5：`user_preference` 兜底必须显式传入

- **决策**：由调用方通过 `initialize(InitRequest { user_preference, legacy_locale })` **显式传入**语言。
- **备选**：依赖 `sys-locale` 自动探测系统语言。
- **理由**：第 9 章结论——`sys-locale` 在 OHOS 上只读四个环境变量（`LANGUAGE` / `LC_ALL` / `LC_MESSAGES` / `LANG`），**不读 HarmonyOS 系统设置**；若进程没有这些环境变量，`get_locales()` 返回空 → 回落 `en-US`。所以要中文生效，必须显式传入（后续应照 colorMode 的模式由 ArkTS 侧带语言进来）。

## 决策 6：回退靠备份，不靠 git

- **决策**：落地前把要改的每个仓库文件备份到 `tmp/i18n-landing-backup/`，回退时用备份还原。
- **备选**：用 `git checkout` / `git restore` 回退。
- **理由**：git 使用规则**禁止** `checkout` / `reset` / `stash` 等分支 / 工作区管理指令，只能做下载、比较、本地提交。所以回退**只能靠备份**。

## 决策 7：对 1.21 与 1.23 的差异做「自洽校验」而不是只看数量

- **决策**：用 `needs_review = 160` 与「status 差值 = 64」双向对齐两版差异，作为提取正确性的自洽证据。
- **备选**：只看「新增/消失」的绝对数量。
- **理由**：数量本身不能证明提取口径一致；用 status 分布与键集合差**互相印证**，才能说明「差异来自内容变化，而非提取口径变化」（侧证：两版 kind 集合完全相同，均 199 种）。
