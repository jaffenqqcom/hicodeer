第 7 章把新增 160 条分了层；本章记录**为其中需要翻译的部分补齐译文**的过程与产物。

## 8.1 复现口径（112 条 = 三个清单）

- **清单1**：`crates/settings_content/src/qemu.rs` 全部新增键 **28 条**。
- **清单2**：指定 **7 个文件**内新增键 **22 条**。
- **清单3**：其余新增键中的 `rust_doc_comment`（**排除以 `"` 开头的 40 条代码 / 配置行**）**62 条**。
- 28 + 22 + 62 = **112**。
- 实测核对：`tmp/i18n-supplement/keys-112.json` 恰好是三个清单，键名为 `list1_qemu_28`（28 条）/ `list2_upstream_visible_22`（22 条）/ `list3_upstream_doc_62`（62 条），总数 112。

## 8.2 可译性判定

对这 112 条按可译性分三类：

- 常规文案：**39 条**。
- 枚举代号：**20 条**（如 `Cpu4` / `Mem8` / `Disk256`）。
- 片段 / 不完整句：**53 条**。

附加标签：

- 含占位符：**8 条**（实测：`{}`、`{error}`、`{file_count}`、`{file_label}`）。
- 含品牌 / 专名：`Zed` **2**、`QEMU` **1**、`OpenCode` **1**、`Git` / `TCG` / `Rust` 各 **1**（实测一致）。

## 8.3 术语一致性做法（方法论）

目的：新补的译文**与既有词表风格一致**，不要同一概念出现多种译法。

做法：

1. 从已有 `translations/zh-CN.json` 里**抽出本批涉及的概念术语**。
2. **看它原来怎么译**，逐条给出「英文术语 → 既有中文译法 + 出处 key」。
3. 结果：**31/31 都能找到出处**（说明既有词表已覆盖这些概念的译法）。
4. 找不到既有译法的（`QEMU` / `vCPU` / `TCG` / `guest` / `gigabytes`）标注「**本次新定**」。

举例（英文术语 → 既有中文译法）：

- `Threads Sidebar` → 会话侧边栏
- `edit predictions` → 编辑预测
- `language scopes` → 语言作用域
- `Stage` → 暂存
- `Unstage` → 取消暂存
- `Trash` → 移至回收站
- `Discard Changes` → 放弃更改
